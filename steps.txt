Steps for the exam

Part (a), validator: validate_schedule() is plain Python and returns every rule violation as a string. It checks room clash, faculty clash, capacity, labs only in LAB1 for 2 consecutive slots, and rooms that are offline.
Part (b), baseline: run ANTHROPIC_API_KEY=... python multiagent.py --llm. One LLM sees all the data and its timetable is validated.
Part (c), agents: each DeptAgent receives only its own sections and preferences. The Mediator sees proposals only, and the Room Manager sees rooms only. Each has its own prompt.
Part (d), messages: agents exchange JSON messages (CFP, PROPOSE, COUNTER, ACCEPT, CONFLICT, COMMIT), and every message goes to message_log.json. Negotiation stops at 0 violations or 8 rounds.
Part (e), disruption: at round 3, R2 goes offline on Tuesday. Only the sections sitting in R2 on Tuesday are sent back, and they try other rooms at the same slot first.
Part (f), results table: the script prints it at the end. Add your 2-line conclusion yourself, for example: “Multi-agent gives 0 violations and more preferences, because the validator feedback loop fixes clashes that a single pass misses.”
